# Oak ↔ Sail RISC-V bridge

The Sail RISC-V model is the ratified golden model of the ISA. This lake
project imports its Lean export and proves that the RV64 semantics Oak's
assembler verifier transliterates (`spec/lean/Oak/RiscV.lean`) agree with
the model's own definitions, instruction by instruction, for the subset
the verifier decides (`docs/spec/94-assembler.md` §9).

The bridge lives in its own project because the Sail export pins Lean
v4.29.0 while Oak's specification uses a newer toolchain. The Oak
definitions it checks are restated verbatim in `OakSailBridge/RiscV.lean`;
`asm/rv64_sail_bridge_test.go` fails if they drift from
`spec/lean/Oak/RiscV.lean`, and runs `lake build` here when the export is
present.

Generating and building the export (once; it is large):

```sh
cd external/sail-riscv
cmake --build build --target generated_lean_rv64d
cd build/model/Lean_RV64D && lake update && lake build
cd ../../../../spec/lean-sail && lake build
```

## Status

The export generated by the opam release of Sail (0.20.2) does not
compile: `Defs.lean` has unbound type-level variables (`k_v` in
`root_level`), and `shift_bits_right_arith` shifts by an `Int` the pinned
lean-sail `v4` has no instance for. sail-riscv's own CI generates with
Sail from git; on this host that opam build fails in the sandbox at
libsail's manifest step. Until a newer Sail is installed the theorems are
checked in Oak's own project, `spec/lean/Oak/SailRiscVBridge.lean`, against
verbatim copies of the library and prelude definitions, and
`asm/rv64_sail_bridge_test.go` keeps those copies honest against the
fetched sources.
